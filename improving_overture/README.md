## improving_overture: steps to clean small buildings, overlaps, and false positives from the integrated Overture/3D-GloBFP

### Notebook 1: GEE Extraction of raster products to building footprints (step1_get_gee_data.ipynb)

Cell 1 extracts Earth Engine raster information for each building footprint and joins the results back to the original building GeoPackage. The workflow takes a city which is matched to the integrated Overture/3D-GloBFP footprints for that city. The outputs are written to a csv: {city}_buildings_alpha_dynamic_25d.csv and geopackage: {city}_overture_buildings_gee.gpkg. It assigns or uses new_id as the join field, removes empty geometries, fixes invalid geometries, and reprojects the processing copy to EPSG:4326. Dynamic World and AlphaEarth are extracted for YEAR = 2025 at SCALE = 10 m, while Google Open Buildings 2.5D is extracted for GOOGLE_25D_YEAR = 2023 at GOOGLE_25D_SCALE = 4 m. To avoid GEE errors, buildings are processed in batches of BATCH_SIZE = 5000, with a PAUSE_SECONDS = 0.5 delay between requests. Dynamic World and AlphaEarth use mean values within each footprint, while Google 2.5D uses the maximum building_presence confidence within each footprint. The cell then calculates the top Dynamic World class, top class probability, built probability, renames the 64 AlphaEarth bands with an alphaearth_ prefix, removes duplicate new_id records, and exports a CSV and GeoPackage containing the original buildings plus GEE-derived attributes.

Cell 2 uses the GEE-enriched GeoPackage to identify AlphaEarth spectral outliers and create t-SNE coordinates for visualization. It reads {city}_overture_buildings_gee.gpkg, expects EXPECTED_ALPHA_BANDS = 64, and keeps only buildings with complete AlphaEarth embeddings for the outlier analysis. The 64 AlphaEarth variables are converted to numeric values and standardized before running an Isolation Forest model. The model parameters are IF_CONTAMINATION = 0.05, IF_N_ESTIMATORS = 300, RANDOM_STATE = 42, and n_jobs = -1. The Isolation Forest labels anomalies as outliers, calculates an anomaly score, and normalizes that score from 0 to 1. The same standardized AlphaEarth feature matrix is then reduced to two dimensions using t-SNE with TSNE_PERPLEXITY = 30, learning_rate = "auto", init = "pca", and RANDOM_STATE = 42. The resulting fields, including isolation_forest_outlier, anomaly scores, and TSNE1/TSNE2, are joined back to the full original GeoPackage by new_id, preserving buildings that lacked complete embeddings but marking them without model results.

Cell 3 creates diagnostic plots from the Isolation Forest and t-SNE output CSV. It reads {city}_buildings_isolation_forest_tsne.csv from the outlier_results_isolation_forest folder and requires the fields TSNE1, TSNE2, dw_top_class_name, isolation_forest_outlier, and google25d_max_confidence. The cell converts t-SNE coordinates and Google 2.5D confidence to numeric values, drops records without valid t-SNE coordinates, and summarizes the number and percentage of Isolation Forest outliers. Google 2.5D confidence is grouped into low confidence < 0.1, medium confidence < 0.5, high confidence ≥ 0.5, and no data. It then exports three 300 dpi figures: t-SNE colored by Dynamic World class, t-SNE colored by Isolation Forest outlier status, and t-SNE colored by Google 2.5D confidence class.

### Notebook 2: Cleaning and dropping false positives (step2_drop_false_and_clean.ipynb)

Cell 1 combines the six city-level building layers into a single integrated dataset. It reads the Garissa, Kigali, Juba, Tripoli, Dakar, and Johannesburg layers from the ArcGIS geodatabase, reprojects them to a common EPSG:4326 CRS, identifies fields that are common to all six layers, removes fields that are not shared across the datasets, and concatenates the six layers into all_buildings_with_25d. The cell reports the number of input and output buildings and retained fields before saving the merged layer.

Cell 2 applies the false-positive screening rules to the merged building layer. The first check removes buildings that are AlphaEarth Isolation Forest outliers, do not have high geometry confidence, and are not classified as built by Dynamic World or have a top_probability below 0.60. The second check removes buildings with Google Open Buildings 2.5D confidence below 0.10 when the geometry provider is not OSM or the building year is greater than 2023. 

Cell 3 separates the cleaned buildings according to their geometry source, either Overture or 3D-GloBFP for the next step.

Cell 4 prepares the Overture and GloBFP layers for overlap analysis and identifies Overture buildings that duplicate GloBFP footprints. It copies the two input layers to working feature classes, assigns sequential OV_ID and GLO_ID identifiers, calculates the original area of each building, and creates an Overture/GloBFP intersection layer. For every intersecting pair, it evaluates the intersection area relative to the original Overture and GloBFP areas and checks both the IoU threshold and complete containment. Overture buildings are flagged for removal when the IoU exceeds IOU_THRESHOLD = 0.10 or when an Overture footprint is completely contained within a GloBFP footprint. GloBFP buildings are never removed by this process.

Cell 5 removes the Overture buildings identified during the overlap analysis. It deletes the flagged Overture features while leaving the GloBFP layer unchanged, removes the temporary OV_ID and GLO_ID fields, deletes the temporary intersection layer, and calculates final Overture and GloBFP feature counts. 

Cell 6 merges the cleaned Overture and GloBFP layers into a single integrated building layer called all_buildings_25d_cleaned_integrated. 

Cell 7 removes small buildings that fall inside the GHS Urban Centre Database (GHS-UCDB) polygons. It reads the integrated building layer and the GHS-UCDB polygon layer, reprojects the polygon layer when necessary so both datasets use the same CRS, and uses a spatial join to identify buildings that intersect a GHS-UCDB polygon. Buildings are removed only when both conditions are true: the building has area_m2 < 16 and it overlaps a GHS-UCDB polygon. Small buildings inside the GHS-UCDB areas are retained.

Cell 8 removes nested building polygons that are completely contained within another building footprint. It performs a self-spatial join using the within predicate to identify buildings contained by other buildings, removes self-matches, and compares the areas of the contained and containing polygons. When the containing polygon is larger, the larger containing polygon is removed, leaving the smaller contained footprint. 

Cell 9 calculates building-neighborhood statistics for the cleaned dataset using a 50 m edge-to-edge distance threshold. If necessary, the buildings are reprojected to a CRS in meters, and a Shapely STRtree spatial index is used to efficiently identify nearby buildings. For every building, the workflow calculates the mean, minimum, and maximum area of neighboring buildings within 50 m; the mean, minimum, and maximum edge-to-edge distance to those neighbors; and the total number of neighbors within 50 m (nn_count_50m). Buildings without neighbors within 50 m receive zero for the neighbor count and NaN for the neighborhood size and distance statistics. The final variables are added to the building layer and written back to the geodatabase.
